# Rust API

The crate (`rust_css_parser`) is a file by file port of the TypeScript sources: the module tree mirrors `src/` of
the TypeScript project, and the functions keep their names in snake case. The [API reference](./api/rust_css_parser/index.html)
is generated from the Rust sources (`npm run doc`).

## Modules

| Module | TypeScript | Content |
|--------|------------|---------|
| `parser::tokenize` | `parser/tokenize.ts` | tokenizer |
| `parser::parse` (`parse_main`) | `parser/parse.ts` | `do_parse()`, `do_parse_sync()`, `parse_string()`, `parse_declarations()` |
| `parser::declaration` | `parser/declaration/*` | `PropertyList`, shorthand computation |
| `ast::arena` | `ast/arena.ts` | the arena: column storage of the nodes and tokens |
| `ast::minify`, `ast::features` | `ast/minify.ts`, `ast/features/*` | minification and its features |
| `ast::transform`, `ast::math` | `ast/transform/*`, `ast/math/*` | transform functions, `calc()` evaluation |
| `printer::render` | `printer/render.ts` | `do_render()`, `render_value()` |
| `printer::sourcemap`, `printer::lib` | `printer/sourcemap.ts`, `printer/lib/codec.ts` | source maps |
| `syntax::color` | `syntax/color/*` | color parsing and conversion |
| `validation` | `validation/*` | syntax validation |
| `host` | — | the callbacks of the host (visitors, `load()`, ...) and the executor of the async parse |
| `bindings` | `node.ts`, `web.ts` | the N-API and WebAssembly bindings, see [Bindings](./bindings.md) |

## Parse and render

The entry points of the TypeScript library (`parse()`, `transform()`, ...) are JavaScript functions: in Rust, the parse
is created from a tokenizer and the options, then rendered.

```rust
use rust_css_parser::host::NoHost;
use rust_css_parser::options::{ParserOptions, SourcesMap};
use rust_css_parser::parser::input::CssInput;
use rust_css_parser::parser::parse::do_parse_sync;
use rust_css_parser::parser::source::SourceFile;
use rust_css_parser::parser::tokenize::{create_parse_info, Tokenizer};
use rust_css_parser::printer::render::do_render;
use std::rc::Rc;

let css = ".a { color: rgb(255 0 0); width: calc(1px + 2px) } .b { color: red }";

// the source file: the locations, the source maps and the string table refer to it
let source = SourceFile::new(Rc::from(css), Vec::new(), Some(Rc::from("in.css")));
let sources = SourcesMap::default();
sources.borrow_mut().insert(source.id, source.clone());

let options = ParserOptions { minify: Some(true), source: Some(source.clone()), sources_map: Some(sources), ..Default::default() };
let tokenizer = Tokenizer::new(create_parse_info(Some(&CssInput::from(css)), source));

// NoHost: no javascript callbacks (visitors, load(), ...)
let result = do_parse_sync(tokenizer, options, None, Rc::new(NoHost)).expect("parse");

// the ast is a node id of the arena
assert_eq!(result.arena.child_count(result.ast), 2);

let rendered = do_render(&result.arena, result.ast, &ParserOptions { minify: Some(true), ..Default::default() }, None);

assert_eq!(rendered.code(), ".a{color:red;width:3px}.b{color:red}");
```

The example is the test `tests/docs_rust_api.rs`.

The callbacks of the options (visitors, `load()`, `generateScopedName`) are called through a `Host`: `NoHost` when
there is none. `do_parse()` is the async version: it awaits the promises of the host (`load()` of the imported files). Both provide every feature (`@import` resolution, css modules loaded from files, ...): `do_parse_sync()` runs `do_parse()` to completion, a host promise that is still pending is an error.

## The arena

The nodes are ids of the arena, as in the TypeScript library (see [Arena Memory](./arena.md)). The columns are Rust
vectors (`Column<T>`), read with `get()` and written with `set()`:

```rust
let arena = &result.arena;
let rule = arena.first_child.get(result.ast);

for declaration in arena.children(rule) {
    println!("{}", arena.get_name(declaration));
}
```

## Data files

The data embedded by the crate are generated by the ports of the TypeScript scripts, in `scripts/`:

| Command | Script | Output |
|---------|--------|--------|
| `npm run syntax-update` | `scripts/webref.rs` (`scripts/webref.ts`) | `src/data/validation.json` (the syntaxes of the validation, from [@webref/css](https://github.com/w3c/webref/tree/main/packages/css)) |
| `npm run config-update` | `scripts/shorthand/main.rs` (`scripts/shorthand.ts`) | `src/data/properties.json` (the shorthand properties) |

The generators are not part of the library: they are a separate crate, `scripts/Cargo.toml` (`cargo run --release --manifest-path scripts/Cargo.toml --bin webref`).
